### Routes and request/response schemas

- `POST /api/tasks/tasks.list` — request `{}`; response `{ tasks: Task[] }`.
- `POST /api/tasks/tasks.today` — request `{}`; response `TodayProjection` defined below.
- `POST /api/tasks/tasks.create` — request `{ title: string(1..500), notes?: string|null (max 4000), due_at?: ISO-8601|null, priority?: 1|2|3, focus_today?: boolean, repeat_rule?: RepeatRule|null, time_zone?: IANA time-zone, confirmed: boolean }`; response `{ task: Task }`.
- `POST /api/tasks/tasks.natural-add` — request `{ text: string(1..1000), confirmed: boolean }`; response `{ kind: 'task'|'reminder', item: Task|Reminder }`. Ambiguous dates/times return `409 conflict` with `details.status='needs_confirmation'` and a reason; do not guess AM/PM. Medicine/T2 content returns a safe `409 conflict` until the S19 private-vault route exists.
- `POST /api/tasks/tasks.update` — request `{ id: UUID, title?: string, notes?: string|null, due_at?: ISO-8601|null, priority?: 1|2|3, repeat_rule?: RepeatRule|null, focus_today?: boolean, time_zone?: IANA time-zone, confirmed: boolean }`; response `{ task: Task }`.
- `POST /api/tasks/tasks.link-project` — request `{ task_id: UUID, project_id: UUID, confirmed: boolean }`; response `{ linked: true, link_id: UUID|null }`. Store the relationship using `public.memory_links` (`src_type='task'`, `rel='part_of'`, `dst_type='project'`); do not add `tasks.project_id`.
- `POST /api/tasks/tasks.complete` — request `{ id: UUID, confirmed: boolean }`; response `{ task: Task, next_task: Task|null, already_completed?: boolean }`. Completing a recurring task creates exactly one next occurrence; completion must be compare-and-set/idempotent.
- `POST /api/tasks/tasks.cancel` — request `{ id: UUID, confirmed: boolean }`; response `{ task: Task }`.
- `POST /api/reminders/reminders.list` — request `{}`; response `{ reminders: Reminder[] }`.
- `POST /api/reminders/reminders.create` — request `{ text: string(1..500), remind_at: ISO-8601, repeat_rule?: RepeatRule|null, time_zone?: IANA time-zone, task_id?: UUID, confirmed: boolean }`; response `{ reminder: Reminder }`. Reject medicine/T2 payloads from this public table path.
- `POST /api/reminders/reminders.cancel` — request `{ id: UUID, confirmed: boolean }`; response `{ cancelled: true }`.
- `POST /api/reminders/reminders.consume-memory` — request `{ request: MedicineReminderRequest }`; response must not echo private fields. `needs_time_confirmation=true` or missing `date_text` returns `409 conflict` with a safe reason. Otherwise return `409 conflict` until S19 approves and supplies the private-vault adapter; this hand-off is not itself a created reminder.

`RepeatRule` is exactly one of `FREQ=DAILY`, `FREQ=WEEKLY`, `FREQ=MONTHLY`, `FREQ=WEEKLY;BYDAY=MO,TU,WE,TH,FR`, or `null`. Time-zone validation must be IANA-aware; S08 defaults to `Asia/Kolkata`.

### Shared data projection

`Task` contains `{ id, title, due_at, status, priority, focus_today, repeat_rule, time_zone }`; internal `notes` are not exposed to Today/D2 DTOs. (timestamps/source can remain internal or be added by S00 contract). `Reminder` contains `{ id, text, remind_at, repeat_rule, time_zone, state }` (task_id and timestamps may be included if useful).

`TodayProjection` is:

```ts
{
  date: string;                 // owner-local YYYY-MM-DD
  time_zone: string;
  focus: {
    open_count: number;
    overdue_count: number;
    top_tasks: Task[];          // max 3, no T2 details
  };
  schedule: Array<{
    id: string;
    kind: 'task' | 'reminder';
    title: string;              // reminder title is generic, never private medicine text
    at: string;                 // ISO timestamp
    status: string;
    priority?: 1|2|3;
  }>;
}
```

No new event is required for this bundle. Do not add reminder text, medicine labels, memory IDs, or lock-screen display text to generic events, logs, or D2 summaries. D2 S01/S02 can read the same TodayProjection; Home card UI remains their ownership.

## CR-3 — S00/LEAD: approve migration `0060_s08_tasks_reminders.sql`

Do not edit an already-applied migration. Antigravity applies this new migration only after LEAD acceptance. Proposed SQL:

```sql
alter table public.tasks
  add column if not exists repeat_rule text,
  add column if not exists time_zone text not null default 'Asia/Kolkata';

alter table public.reminders
  add column if not exists time_zone text not null default 'Asia/Kolkata',
  add column if not exists approved_decision_id uuid null
    references public.decisions(id) on delete set null;

do $$
begin
  if not exists (
    select 1 from pg_constraint
    where conname = 'tasks_repeat_rule_s08_ck'
      and conrelid = 'public.tasks'::regclass
  ) then
    alter table public.tasks
      add constraint tasks_repeat_rule_s08_ck
      check (repeat_rule is null or repeat_rule in (
        'FREQ=DAILY', 'FREQ=WEEKLY', 'FREQ=MONTHLY',
        'FREQ=WEEKLY;BYDAY=MO,TU,WE,TH,FR'
      )) not valid;
  end if;
  if not exists (
    select 1 from pg_constraint
    where conname = 'reminders_repeat_rule_s08_ck'
      and conrelid = 'public.reminders'::regclass
  ) then
    alter table public.reminders
      add constraint reminders_repeat_rule_s08_ck
      check (repeat_rule is null or repeat_rule in (
        'FREQ=DAILY', 'FREQ=WEEKLY', 'FREQ=MONTHLY',
        'FREQ=WEEKLY;BYDAY=MO,TU,WE,TH,FR'
      )) not valid;
  end if;
end $$;

create index if not exists tasks_owner_due_s08_idx
  on public.tasks(owner_id, due_at)
  where status in ('todo', 'doing') and due_at is not null;

create index if not exists reminders_owner_due_s08_idx
  on public.reminders(owner_id, remind_at)
  where state = 'pending';

create index if not exists reminders_approval_s08_idx
  on public.reminders(approved_decision_id)
  where approved_decision_id is not null;
```

The nullable `approved_decision_id` is deliberate: old reminder rows have no S08 consent proof and the new worker must not fire them. New API-created reminders link to their pre-written `decisions` row. S08 does not add/modify a migration file in this patch.

## CR-6 — S22: register the S08 powers

Create these registry rows with `owner_squad='S08'`, `autonomy_default=0`, `autonomy_current=0`, `needs_confirm=true`, and `max_level=2`:

| Power ID | Tags | Reversible | Description |
|---|---|---:|---|
| `tasks.create` | `['personal']` | true | Create an owner task |
| `tasks.update` | `['personal']` | true | Update owner task fields |
| `tasks.complete` | `['personal']` | true | Complete task and advance repeat |
| `tasks.cancel` | `['personal']` | true | Cancel owner task |
| `tasks.link-project` | `['personal']` | true | Link task to owner project |

| `reminders.cancel` | `['personal']` | true | Cancel pending reminder/job |

Every row starts at L0 and therefore denies execution until Amit raises it under S22 policy. L2 requires an explicit owner confirmation; the API records that confirmation in the `decisions` row before creating the reminder. `reminders.fire` is allowed to pass `confirmed=true` to the worker gate only after the worker verifies `approved_decision_id` points to the same owner's `reminders.create` decision with `level>=2` and a non-blocked intent/result. Repeating reminders retain that original approval link. Never turn on a reminder worker with missing/invalid approval proof.

## CR-7 — S00 + S16A: register worker handler and notification adapter

- `requeue`: insert the next `reminders.fire` job with idempotency key `reminders.fire:<reminder-id>:<next-run-at>`.

No new scheduler package is required for this integration: the existing `worker/jobs` queue is the selected firing mechanism. The `packages/scheduler` folder is not built; do not invent or bypass it.
