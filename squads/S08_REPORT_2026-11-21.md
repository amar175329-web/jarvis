- One function `api/tasks/index.ts` handles both groups via rewrites to respect the stated Vercel Hobby function cap. No `api/reminders/*` file is added.
- Owner auth copies `api/chat`'s `readOwnerSession` pattern. PostgREST uses anon key + owner access token; no service key in app/API.
- Mutations pre-write a minimal audit intent, then call `executePower`; missing power, L0/L1, missing confirmation, kill switch ON/unreadable, or audit-intent failure blocks the write.
- Reminder rows carry `approved_decision_id` through proposed migration so worker can verify the original owner's schedule consent before it passes `confirmed=true` to `reminders.fire`.
- Natural language parsing is deterministic; no model call is made. This avoids hard-coded model/price and keeps private content out of non-local model paths.
- Medicine/T2 text is never placed into `public.reminders`, generic Today schedule labels, worker payloads, or logs. S09 hand-off is validated but not persisted until S19 provides the approved vault.
- Recurring tasks advance on explicit task completion; recurring reminders advance in the worker. Late runs skip missed occurrences instead of immediately replaying a backlog.
- Today page content is distinct from D2 Home cards; it provides the reusable `TodayProjection`. Home, shell, tokens, reference HTML, `packages/contracts`, migrations, and worker source are untouched.
