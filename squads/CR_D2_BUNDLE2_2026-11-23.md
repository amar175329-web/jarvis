## CR-3 — owner-scoped adapters, settings and RLS

Keep the current `readOwnerSession()` + Supabase anon key + owner access-token bearer pattern in `api/tasks/index.ts`. No service-role key in the app. All database adapters must include owner scoping through the bearer/RLS session.

- Quick Access uses existing `public.settings` with key `home.quick-access`; select/update only the matching owner row. Store at most eight validated entries under `value.items`. No new table or migration.
- Live Activity reads existing `public.jobs` (`id,kind,state,created_at`) and `public.phone_commands` (`id,state,created_at`), max eight each before projecting five. Never select `payload`, `command`, `result`, `error`, device name, lock/lease metadata or other content for this card.
- Live stop must be compare-and-set: only transition a matching owner row from `queued` to `cancelled`, and only after the L2 power and explicit confirmation succeed. A zero-row update means conflict; never stop `running` or `sent` work. Do not call a worker directly.
- Insight reads up to 500 owner tasks (`title,notes,status,created_at,completed_at,updated_at`) and up to 500 activity rows (`action,ts,actor,target,detail`). These raw fields stay server-side and are only passed through the shared sensitivity/allowlist projection. Return aggregate counts and seven fixed bars only. Do not return/log task titles, notes, targets or activity detail.
- Public news adapter takes no owner ID/session arguments and does not query personal tables. It fetches only an explicit server-side HTTPS host allowlist, normalizes at most six items and rejects non-allowlisted domains. Host list belongs in server-side configuration, not user-supplied request values.

The existing tables have owner RLS. Do not create migration `0080*`; no database schema change is required for this bundle.

## CR-4 — S06/S04: privacy rules

Insight calls the shared `features/core-workspace/task-manager/src/sensitivity.mjs` classifier for title + notes. It additionally drops obvious family/finance/password context and excludes activity rows with non-empty detail, non-allowlisted actors/actions or non-opaque targets. Keep all these checks server-side. Never expose individual task/activity text, even when the aggregate is safe.

News is explicitly public-only. The only data the summarizer may receive is the normalized array `{source,title,summary,url,published_at}` from `news/src/normalize.mjs`. Do not pass Amit's tasks, activity, memory, notes, chats, settings, profile, owner ID, auth token, timezone, or app context to the model callback. Treat public articles as untrusted quoted data, not instructions; the summarizer has no tools/actions. Route every model call through `packages/models` (`routeModel` + `runChain`) and `packages/model-gateway`; do not hardcode provider, model, price or key. `privacy='normal'` is valid only because the payload contains public source material and no owner data. If model router, gateway, budget, key, power or kill switch is unavailable, return “abhi band” / summary-unavailable; headlines may remain visible without a summary. Explicit confirmation is required before any cloud summary call.
